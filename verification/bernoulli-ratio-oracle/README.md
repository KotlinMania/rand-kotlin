# Bernoulli ratio typed-result parity

## Exact source contract

`tmp/rand/src/distr/bernoulli.rs` defines `Bernoulli::from_ratio(u32,u32) -> Result<Bernoulli,BernoulliError>`. It rejects numerator > denominator or denominator == 0 before the equal-ratio always-true branch, otherwise preserves the existing floating division/scaling threshold. BernoulliError has the single InvalidProbability variant and the Display string `p is outside [0, 1] in Bernoulli distribution`. Kotlin instead threw from this constructor and omitted the error type.

The bounded manual consumer repair adds the source-owned BernoulliError enum and reuses the existing canonical distr.Result; no duplicate Result/helper/error owner is introduced. fromRatio now returns that typed result with exact source validation order. Sampling/p(), probability scaling, the separate create(Double) constructor and randomBool are unchanged. The latter probability-constructor API still differs from upstream new(p) and is explicitly outside this step; do not infer complete Bernoulli translation from this repair.

The directly affected Rng.randomRatio caller now matches Ok/Err as upstream `rng.rs` does: Ok delegates to sample, Err panics with `p=n/d is outside range [0.0, 1.0]`. UInt decimal formatting matches the integer source fields without substituting a floating formatter. The one existing BernoulliTest caller adds unwrap; its tolerance, expected values and assertions are otherwise byte-for-byte unchanged. No compatibility overload perpetuates the throwing constructor contract.
